# feature_structure

[![Powered by Mason](https://img.shields.io/endpoint?url=https%3A%2F%2Ftinyurl.com%2Fmason-badge)](https://github.com/felangel/mason)

Scaffolds a complete Clean Architecture feature — domain, data and
presentation — for a [vgv_cli](https://github.com/victorsdd01/vgv_cli) project.

## What you get

```
<feature_name>/
├── domain/
│   ├── repositories/<feature>_repository.dart      # abstract interface
│   └── use_cases/<feature>_use_cases.dart          # calls the repository
├── data/
│   ├── datasources/
│   │   ├── local/<feature>_local_datasource.dart   # saveData() stub
│   │   └── remote/<feature>_remote_datasource.dart # fetchData() stub
│   └── repositories/<feature>_repository_impl.dart
└── presentation/
    ├── blocs/
    │   ├── blocs.dart                              # barrel
    │   └── <feature>_bloc/                         # if include_bloc
    │       ├── <bloc>_bloc.dart                    # HydratedBloc + freezed
    │       ├── <bloc>_event.dart
    │       └── <bloc>_state.dart
    └── pages/<page>_page.dart                      # if add_page
```

Everything returns `Either<Failure, T>` (dartz), matching the rest of a vgv
project. The datasource bodies are stubs — swap the `Future.delayed` for your
real API or database calls.

## Variables

| Variable | Type | Default | What it is |
|---|---|---|---|
| `project_name` | string | `my_app` | Your package name, used to build the imports |
| `feature_name` | string | — | Feature name, e.g. `orders` → `OrdersRepository`, `orders/` |
| `include_bloc` | boolean | `false` | Generate the bloc trio |
| `bloc_name` | string | — | Bloc class name (only used when `include_bloc`) |
| `add_page` | boolean | `true` | Generate a page |
| `page_name` | string | — | Page class name (only used when `add_page`) |
| `choose_page_type` | boolean | `true` | `true` = Stateless, `false` = Stateful |
| `add_bloc_to_page` | boolean | `true` | Wire the bloc into the page |

`bloc_name` does not have to match `feature_name`.

## Usage

Render into `lib/features` — the brick creates the `<feature_name>/` folder:

```sh
vgv gen brick feature_structure \
  --url https://github.com/victorsdd01/flutter_bricks -o lib/features
```

Or with mason directly:

```sh
mason add -g feature_structure \
  --git-url https://github.com/victorsdd01/flutter_bricks \
  --git-path feature_structure
mason make feature_structure -o lib/features
```

## After generating

1. Run codegen if you included a bloc:
   ```sh
   dart run build_runner build -d
   ```
2. Register the pieces in `application/injector.dart`:
   ```dart
   injector
     ..registerLazySingleton<OrdersRemoteDataSource>(OrdersRemoteDataSourceImpl.new)
     ..registerLazySingleton<OrdersRepository>(
       () => OrdersRepositoryImpl(
         ordersRemoteDataSource: Injector.get<OrdersRemoteDataSource>(),
       ),
     )
     ..registerLazySingleton<OrdersUseCases>(
       () => OrdersUseCases(repository: Injector.get<OrdersRepository>()),
     )
     ..registerFactory<OrdersBloc>(
       () => OrdersBloc(ordersUseCases: Injector.get<OrdersUseCases>()),
     );
   ```
3. Add the page's route in `application/routes/routes.dart`.

> `vgv gen feature <name>` does this wiring for you; this brick leaves it to
> you so it stays usable in projects with a different setup.

## Expects

A project generated by vgv_cli: `TStateless` / `TStateful` (`core/states/`),
`Injector` (`application/injector.dart`), `S`
(`application/generated/l10n.dart`), a `Failure` type with `ServerFailure` and
`CacheFailure` (`core/errors/failures.dart`), and `dartz`, `hydrated_bloc` and
`freezed_annotation` as dependencies.
